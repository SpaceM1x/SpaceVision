# SpaceVision — оценка риска лесных пожаров

Веб-приложение для оценки вероятности лесных пожаров на территории Заиграевского
района (Республика Бурятия). Карта риска — единый модуль: после выбора точки
можно посчитать риск по формуле, получить диапазон годовой вероятности или
независимую оценку по ИИ-модели.

## Возможности

### Общее
- Авторизация по логину/паролю (`admin / admin123`, `operator / operator123`).
- Плоское боковое меню: «Обзор», «Карта риска», «Дороги», «ИИ-оценка снимка»,
  «История», «Статистика», «Документы», «Личный кабинет».
- SQLite-база, состояние сохраняется между запусками.

### Карта риска
- Одна карта (схема / спутник) с кнопкой-прицелом.
- После выбора точки в правой панели предлагается метод:
  - **Формула** — объяснимый логистический расчёт по дорогам, поселениям,
    сезону, времени суток и погодному индексу Нестерова;
  - **Диапазон** — нижняя, средняя и верхняя годовая вероятность по
    экспоненциальной модели затухания от дорог и населённых пунктов;
  - **ИИ-модель** — классификация космоснимка участка предобученной SigLIP2.
- Результаты методов различаются: формула показывает вклад каждого фактора,
  диапазон — три сценария параметров, ИИ-модель — класс поверхности,
  уверенность, распределение классов и снимок.
- История расчётов хранит метод и полное объяснение.

### Дороги
- Загрузка ESRI Shapefile (`.shp`, `.shx`, `.dbf`, `.prj`, опционально `.cpg`).
  Файл `.prj` обязателен: CRS не угадывается.
- Слой сразу используется на карте риска для расстояния до дороги и плотности.
- Распознавание дорог по космоснимку нейросетью U-Net: маска и оверлей.
- Очистка загруженных SHP и история обработанных снимков.

### Остальное
- **ИИ-оценка снимка** — предобученная модель SigLIP2
  (`prithivMLmods/Fire-Risk-Detection`, Apache-2.0): 7 классов поверхности,
  уверенность и непрерывный индекс риска.
- **Статистика** — доля дорог, тренд, топ снимков.
- **Документы** — заглушка модуля исторических материалов.
- **История** — вкладки «Расчёты риска» и «Снимки».

## Сезонная логистическая формула (метод «Формула»)

Логистическая модель (коэффициенты — лог-шансовые веса, `b`):

```
x_road       = 1 / (1 + d_road / R0)          # R0 = 500 м
x_settlement = exp(-d_settlement / 3000)

N (Нестеров) = Σ max(Tmax, 0) · max(Tmax − Td, 0)
               по сухим дням; сброс при осадках ≥ 3 мм
FWI          = clamp((N − 300) / 4700, 0, 1)

logit(P) = b0 + b_road·x_road + b_settlement·x_settlement
         + b_road_density·ρ_дорог + b_settlement_density·ρ_поселений
         + b_season·сезон + b_diurnal·суточ + b_fwi·FWI
         + b_interaction·x_road·x_settlement

P_fire = 1 / (1 + exp(−logit(P)))
```

- `d_road` — расстояние до ближайшей дороги из загруженного SHP, при его
  отсутствии — из OSM. Дорога учитывается **один раз**: `P_fire = P_base`.
- `d_settlement`, `ρ_дорог`, `ρ_поселений` — контекст OSM (Overpass).
- `FWI` — погодный индекс Нестерова по данным NASA POWER за последние 30 дней.
  Если API недоступен или данных нет, используется климатическая норма месяца.
- `сезон` — сезонный фактор `[0,1]` (июль — максимум, январь — минимум).
- `суточ` — суточный фактор `[0,1]` (пик в 15:00 местного времени).
- Пороговые уровни: низкий `< 2%`, средний `2–10%`, высокий `≥ 10%`.
- Текущие коэффициенты заданы вручную и обеспечивают монотонность и
  ограниченность `P ∈ (0,1)`; их следует заменить на обученные и
  откалиброванные по историческим данным (например, очаги FIRMS).

## Диапазонная модель (метод «Диапазон»)

Метод оценивает вероятность **хотя бы одного пожара за год** на площади `A`
по расстояниям до ближайшей дороги и населённого пункта:

```
λ = λ₀ · exp(−β · R_road) · exp(−γ · R_settlement)
P = 1 − exp(−λ · A)
```

- `λ` — ожидаемая интенсивность, пожаров на 1 га в год;
- `R_road`, `R_settlement` — расстояния в метрах;
- `A` — площадь расчёта в гектарах (по умолчанию `1.0`);
- `P` — вероятность хотя бы одного пожара; модель считает поток пожаров
  пуассоновским.

Параметры трёх сценариев:

| Сценарий | λ₀, пож./(га·год) | β, 1/м | γ, 1/м |
|---|---:|---:|---:|
| Нижняя граница (консервативная) | 0.0006 | 0.0035 | 0.0018 |
| Средний (базовый) | 0.0012 | 0.0025 | 0.0012 |
| Верхняя граница (повышенный риск) | 0.0025 | 0.0018 | 0.0009 |

Уровень риска определяется по **базовому** сценарию:

| Годовая вероятность на 1 га | Уровень |
|---|---|
| `< 0.01%` | очень низкий |
| `0.01–0.05%` | низкий |
| `0.05–0.15%` | умеренный |
| `≥ 0.15%` | повышенный |

Это относительные классы для годовой вероятности, а не официальные классы
пожарной опасности. Три сценария — не доверительный интервал, а диапазон
неопределённости параметров. Коэффициенты предварительные и не откалиброваны
по историческим пожарам; для конкретного региона модель нужно калибровать.

### Автоматические расстояния

`GET /risk/point?lat=...&lon=...&method=range&area_ha=1`:

1. расстояние до дорог берётся из загруженного SHP, иначе из OSM;
2. расстояние до населённых пунктов берётся из `SETTLEMENTS_SHP_PATH`,
   если слой есть, иначе из OSM;
3. если оба источника недоступны, API возвращает `422` с понятным
   сообщением, а не подставляет вымышленное расстояние.

Расстояния можно передать явно: `road_distance_m` и `settlement_distance_m`
имеют приоритет над слоями и OSM. Это удобно для сценарного расчёта, когда
векторных слоёв нет. В интерфейсе карты для метода «Диапазон» есть поля
«До дороги, м» и «До поселения, м»: пустые поля означают автоматический
расчёт, заполненные — ручной.

Для локального слоя населённых пунктов положите Shapefile в
`gis/settlements/settlements.shp` (или задайте `SETTLEMENTS_SHP_PATH`).
Поддерживаются точечные и полигональные слои с обязательным `.prj`.

Пример ответа (сокращённо):

```json
{
  "method": "range",
  "road_distance_m": 100.0,
  "settlement_distance_m": 500.0,
  "area_ha": 1.0,
  "base_probability": 0.0005127,
  "fire_probability": 0.0005127,
  "risk_level": "moderate",
  "risk_level_ru": "умеренный",
  "probability_range": {
    "lower": {"percent": 0.0172},
    "base": {"percent": 0.0513},
    "upper": {"percent": 0.1331}
  }
}
```

### Примеры расчёта

Запуск из каталога `backend`:

```bash
python -X utf8 -m app.fire_probability
```

Фрагмент вывода:

```

       100          500     1.0      0.0172       0.0513       0.1331  умеренный
```

### Использование из Python

```python
from app.fire_probability import calculate_fire_probability

result = calculate_fire_probability(
    road_distance_m=100.0,
    settlement_distance_m=500.0,
    area_ha=1.0,
)
print(result.lower.percent, result.base.percent, result.upper.percent)
print(result.risk_level_ru)
print(result.explanation())
```

Для автоматического расчёта расстояний по координатам можно передать
`VectorLayerCache` из `app.vector_data.build_vector_cache`:

```python
from app.point_probability import calculate_point_fire_probability
from app.vector_data import build_vector_cache

roads = build_vector_cache("gis/roads/roads.shp", label="road")
settlements = build_vector_cache("gis/settlements/settlements.shp", label="settlement")

point = calculate_point_fire_probability(
    51.80, 108.05, area_ha=1.0, roads=roads, settlements=settlements
)
print(point.result.base.percent, point.road.source, point.settlement.source)
```

## ИИ-метод по точке

`GET /risk/point?lat=...&lon=...&method=ai`:

1. По координате определяется тайл Esri World Imagery z15 (кэш —
   `backend/data/satellite_tiles`).
2. SigLIP2 классифицирует снимок участка.
3. Индекс риска модели `risk_score ∈ [0,1]` переводится в вероятность:

```
P_AI = 0.005 + 0.30 · risk_score^1.6
```

Это вспомогательная оценка поверхности по снимку, а не официальный прогноз
возгорания. Для метода `formula` (по умолчанию) используется сезонная
логистическая формула, для `range` — диапазонная годовая модель.

## Предобученная модель по снимку

В разделе «ИИ-оценка снимка» используется открытая модель
`prithivMLmods/Fire-Risk-Detection` (SigLIP2, Apache-2.0), обученная на
`blanchon/FireRisk`. Она классифицирует RGB-снимок по 7 классам:
`very_low`, `low`, `moderate`, `high`, `very_high`, `non-burnable`, `water`.

- Модель загружается лениво: первый запуск скачивает ~370 МБ в кэш
  Hugging Face (`~/.cache/huggingface`), затем загрузка занимает несколько
  секунд.
- API: `GET /ai/fire-risk/status`, `POST /ai/fire-risk/preload`,
  `POST /ai/fire-risk/image` (multipart, поле `file`).
- Модель можно отключить: `FIRE_RISK_MODEL_ENABLED=0`.

## Скорость и устойчивость

- OSM (Overpass) — необязательный контекст: короткий таймаут, кэш и
  предохранитель после ошибки. Для полностью офлайн-режима: `OSM_ENABLED=0`.
- NASA POWER — короткий таймаут, кэш на 6 часов и предохранитель на 10 минут;
  при недоступности используется климатическая норма.
- Точечный ИИ-метод требует загруженной модели; пока модель готовится, API
  возвращает понятное сообщение, а интерфейс показывает статус.

## Запуск

Требования: Python 3.10+, Node.js 18+.

```bash
# бэкенд
pip install -r backend/requirements.txt
python -m uvicorn app.main:app --reload --port 8000 --app-dir backend

# фронтенд
cd frontend && npm install && npm run dev
```

Или всё сразу из корня: `npm start`.

Фронтенд: http://localhost:5173, API: http://localhost:8000 (документация — `/docs`).

## Тесты

```bash
cd backend && python -m pytest
cd frontend && npm run build
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ROADS_SHP_PATH` | путь к Shapefile дорог | `gis/roads/roads.shp` |
| `SETTLEMENTS_SHP_PATH` | путь к Shapefile населённых пунктов (опционально) | `gis/settlements/settlements.shp` |
| `R0_METERS` | характерное расстояние влияния дороги | `500` |
| `METRIC_CRS` | метрическая CRS (иначе UTM по центроиду) | пусто |
| `OSM_ENABLED` | использовать Overpass для контекста | `1` |
| `OSM_TIMEOUT_SECONDS` | таймаут запроса к Overpass | `1.5` |
| `OSM_FAILURE_COOLDOWN_SECONDS` | пауза после ошибки Overpass | `300` |
| `OSM_CACHE_TTL_SECONDS` | TTL кэша ответов Overpass | `600` |
| `FIRE_WEATHER_ENABLED` | использовать NASA POWER | `1` |
| `FIRE_WEATHER_TIMEOUT_SECONDS` | таймаут запроса к NASA POWER | `2.0` |
| `FIRE_WEATHER_CACHE_TTL_SECONDS` | TTL кэша погоды | `21600` |
| `FIRE_WEATHER_FAILURE_COOLDOWN_SECONDS` | пауза после ошибки NASA POWER | `600` |
| `FIRE_RISK_MODEL_ENABLED` | включить модель по снимку | `1` |
| `FIRE_RISK_MODEL_ID` | идентификатор модели на Hugging Face | `prithivMLmods/Fire-Risk-Detection` |
| `FIRE_RISK_MODEL_CACHE_DIR` | каталог кэша весов | кэш Hugging Face |
| `FIRE_RISK_MAX_IMAGE_BYTES` | максимальный размер снимка | `20971520` |

## Технологии

FastAPI, SQLAlchemy (SQLite), PyJWT, GeoPandas/Shapely/PyProj, React, Leaflet,
react-leaflet, PyTorch + segmentation-models-pytorch (сегментация дорог),
Transformers + SigLIP2 (предсказание класса поверхности по снимку).
