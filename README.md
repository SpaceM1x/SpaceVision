# SpaceVision — оценка риска лесных пожаров

Веб-приложение для оценки риска лесных пожаров в Заиграевском районе Бурятии.
На карте можно сравнить расчёт по формуле с моделью, обученной на реестре
пожаров. Отдельно доступны распознавание дорог и классификация космоснимка.

## Возможности

### Общее
- Авторизация по логину/паролю (`admin / admin123`, `operator / operator123`).
- Плоское боковое меню: «Обзор», «Карта риска», «Дороги», «ИИ-оценка снимка»,
  «История», «Статистика», «Документы», «Личный кабинет».
- SQLite-база, состояние сохраняется между запусками.

### Карта риска
- Одна карта (схема / спутник) с кнопкой-прицелом.
- После выбора точки в правой панели предлагается метод:
  - **Формула** — годовая вероятность по экспоненциальной модели затухания
    от дорог и населённых пунктов;
  - **ИИ · реестр** — модель, обученная на данных о пожарах в Бурятии.
- Расстояния до дороги и населённого пункта измеряются прямо на карте по
  отображаемым слоям Leaflet.
- Результаты формулы и модели реестра показывают вероятность крупного
  антропогенного пожара (от 200 га) за год и объяснение факторов.
- История расчётов хранит метод и полное объяснение.

### Дороги
- Загрузка ESRI Shapefile (`.shp`, `.shx`, `.dbf`, `.prj`, опционально `.cpg`).
  Файл `.prj` обязателен: CRS не угадывается.
- Слой сразу используется на карте риска для расстояния до дороги и плотности.
- Распознавание дорог на космоснимках моделью сегментации OpenEarthMap:
  единая маска обычных и видимых грунтовых дорог, а также оверлей.
- Очистка загруженных SHP и история обработанных снимков.

Для распознавания используется UPerNet-модель с классом `road`, обученная на
спутниковых снимках OpenEarthMap. Изображение обрабатывается перекрывающимися
тайлами 512×512, чтобы не терять узкие дороги при уменьшении крупных GeoTIFF.
Обычные и грунтовые дороги попадают в одну маску, если различимы на исходном
снимке; модель не определяет тип покрытия отдельно. При первом распознавании
веса (около 240 МБ) скачиваются с Hugging Face и далее берутся из локального
кэша. В карточке источника модели лицензия не указана — проверьте условия её
использования перед коммерческим развёртыванием.

### Остальное
- **ИИ-оценка снимка** — предобученная модель SigLIP2
  (`prithivMLmods/Fire-Risk-Detection`, Apache-2.0): 7 классов поверхности,
  уверенность и непрерывный индекс риска.
- **Статистика** — доля дорог, тренд, топ снимков.
- **Документы** — заглушка модуля исторических материалов.
- **История** — вкладки «Расчёты риска» и «Снимки».

## Формула годовой вероятности (метод «Формула»)

Метод оценивает вероятность **хотя бы одного пожара за год** на площади `A`
по расстояниям до ближайшей дороги и населённого пункта:

```
λ = λ₀ · exp(−β · R_road) · exp(−γ · R_settlement)
P = 1 − exp(−λ · A)
```

- `λ` — ожидаемая интенсивность, пожаров на 1 га в год;
- `R_road`, `R_settlement` — расстояния в метрах;
- `A` — площадь расчёта в гектарах (по умолчанию `1.0`);
- `P` — вероятность хотя бы одного пожара; поток пожаров считается
  пуассоновским.

Параметры модели (усреднённые значения по России):

| Параметр | Значение | Смысл |
|---|---:|---|
| `λ₀` | 0.0012 пож./(га·год) | базовая интенсивность у инфраструктуры |
| `β` | 0.01 1/м | затухание по дорогам (в `e` раз примерно за 100 м) |
| `γ` | 0.0001 1/м | затухание по населённым пунктам (в `e` раз примерно за 10 км) |

Уровень риска определяется по годовой вероятности на 1 га:

| Годовая вероятность на 1 га | Уровень |
|---|---|
| `< 0.024%` | очень низкий |
| `0.024–0.048%` | низкий |
| `0.048–0.072%` | средний |
| `≥ 0.072%` | относительно высокий |

Это относительные классы для годовой вероятности, а не официальные классы
пожарной опасности. Формула оценивает крупные антропогенные пожары из реестра
ИСДМ, а не любые возгорания. Её параметры усреднены по России.

## Модель по реестру пожаров

Второй способ на карте использует модель, обученную на реестре ИСДМ по Бурятии
за 2000–2025 годы. Для оценки учитываются расстояния до дорог, населённых
пунктов и железной дороги, район и месяц. В проекте хранится обученная модель
`ml/fire_point_model/fire_point_model.joblib`; скрипт для её переобучения лежит
рядом. Слои заказчика для расчёта должны быть доступны в папке
`информация от заказчика/БНЦ` или путь можно задать через `FIRE_ML_DATA_DIR`.

### Расстояния из карты Leaflet

Основной источник расстояний — модуль карты: после выбора точки браузер
измеряет расстояние до ближайшего объекта в отображаемых слоях дорог и
населённых пунктов и передаёт его в API.

`GET /risk/point?lat=...&lon=...&method=formula&area_ha=1`:

1. `road_distance_m` и `settlement_distance_m` из карты имеют приоритет;
2. если они не переданы (прямой вызов API), расстояние до дорог берётся из
   загруженного SHP, иначе из OSM;
3. расстояние до населённых пунктов — из `SETTLEMENTS_SHP_PATH`, если слой
   есть, иначе из OSM;
4. если источник недоступен, API возвращает `422` с понятным сообщением,
   а не подставляет вымышленное расстояние.

Слой населённых пунктов для карты отдаёт
`GET /settlements/geojson?lat=...&lon=...&radius_m=40000`: сначала
используется локальный Shapefile, иначе — объекты OSM (Overpass). В ответе
GeoJSON есть поле `source` (`shp` или `osm`).

Для локального слоя положите Shapefile в
`gis/settlements/settlements.shp` (или задайте `SETTLEMENTS_SHP_PATH`).
Поддерживаются точечные и полигональные слои с обязательным `.prj`.

Пример ответа (сокращённо):

```json
{
  "method": "formula",
  "road_distance_m": 200.0,
  "settlement_distance_m": 500.0,
  "area_ha": 1.0,
  "road_influence": 0.1353352832,
  "road_source": "map",
  "base_probability": 0.0001544700,
  "fire_probability": 0.0001544700,
  "risk_level": "very_low",
  "risk_level_ru": "очень низкий",
  "summary": "Годовая вероятность крупного антропогенного пожара (более 200 га) 0.015% (очень низкий) на 1 га."
}
```

Поле `explanation` содержит уравнение, значения параметров, оба множителя
затухания, интенсивность `λ`, пороги уровня и список допущений.

### Примеры расчёта

Запуск из каталога `backend`:

```bash
python -X utf8 -m app.fire_probability
```

Фрагмент вывода:

```
 R_road, м  R_settle, м   A, га   λ, пож./(га·год)   вероятность, %  уровень
----------------------------------------------------------------------------
         0            0     1.0         0.00120000            0.120  относительно высокий
       200          500     1.0         0.00015448            0.015  очень низкий
       500         1000     1.0         0.00000732            0.0007 очень низкий
      1500         3000     1.0         0.00000000          <0.0001  очень низкий
     10000        20000     1.0         0.00000000          <0.0001  очень низкий
```

### Использование из Python

```python
from app.fire_probability import calculate_fire_probability

result = calculate_fire_probability(
    road_distance_m=200.0,
    settlement_distance_m=500.0,
    area_ha=1.0,
)
print(result.percent, result.risk_level_ru)
print(result.lambda_per_ha_year, result.road_decay, result.settlement_decay)
print(result.explanation())
```

Для расчёта расстояний по координатам с резервом на SHP:

```python
from app.point_probability import calculate_point_fire_probability
from app.vector_data import build_vector_cache

roads = build_vector_cache("gis/roads/roads.shp", label="road")
settlements = build_vector_cache("gis/settlements/settlements.shp", label="settlement")

point = calculate_point_fire_probability(
    51.80, 108.05, area_ha=1.0, roads=roads, settlements=settlements
)
print(point.result.percent, point.road.source, point.settlement.source)
```

## ИИ-метод по точке

`GET /risk/point?lat=...&lon=...&method=ai`:

1. По координате определяется тайл Esri World Imagery z15 (кэш —
   `backend/data/satellite_tiles`).
2. SigLIP2 классифицирует снимок участка.
3. Индекс риска модели `risk_score ∈ [0,1]` переводится в вероятность:

```
P_AI = 0.005 + 0.30 · risk_score^1.6
```

Это вспомогательная оценка поверхности по снимку, а не официальный прогноз
возгорания. Метод `formula` (по умолчанию) считает годовую вероятность по
экспоненциальной модели расстояний, метод `ai` — по классификации снимка.

## Распознавание риска по снимку

В разделе «ИИ-оценка снимка» используется открытая модель
`prithivMLmods/Fire-Risk-Detection` (SigLIP2, Apache-2.0), обученная на
`blanchon/FireRisk`. Она классифицирует RGB-снимок по 7 классам:
`very_low`, `low`, `moderate`, `high`, `very_high`, `non-burnable`, `water`.

- Модель загружается лениво: первый запуск скачивает ~370 МБ в кэш
  Hugging Face (`~/.cache/huggingface`), затем загрузка занимает несколько
  секунд.
- API: `GET /ai/fire-risk/status`, `POST /ai/fire-risk/preload`,
  `POST /ai/fire-risk/image` (multipart, поле `file`).
- Модель можно отключить: `FIRE_RISK_MODEL_ENABLED=0`.

## Скорость и устойчивость

- OSM (Overpass) — необязательный контекст и резерв расстояний: короткий
  таймаут, кэш и предохранитель после ошибки. Для полностью офлайн-режима:
  `OSM_ENABLED=0`.
- Расстояния с карты не требуют сетевых запросов; OSM нужен только для
  отрисовки слоя населённых пунктов, если нет локального SHP.
- Точечный ИИ-метод требует загруженной модели; пока модель готовится, API
  возвращает понятное сообщение, а интерфейс показывает статус.

## Структура

```
backend/            FastAPI (auth, roads, risk, uploads, analytics)
  app/
    fire_risk.py       пороги уровня риска (историческая логистическая модель)
    fire_probability.py формула годовой вероятности λ/P
    fire_ml.py          расчёт по модели реестра пожаров
    fire_registry.py    статистика реестра ИСДМ
    fire_history.py     история расчётов
    point_probability.py приоритет расстояний с карты, резерв SHP/OSM
    vector_data.py     загрузка произвольного векторного слоя
    settlement_data.py кэш слоя населённых пунктов
    osm.py             расстояния и GeoJSON населённых пунктов из OSM
    satellite.py       тайлы Esri World Imagery для ИИ-метода
    fire_image.py      SigLIP2: статус, прогрев, классификация
    road_inference.py  распознавание дорог на снимках
  tests/               pytest
frontend/              React + Leaflet
  src/App.jsx          UI
  src/api.js           HTTP-клиент
  src/styles.css
gis/roads/             загруженные Shapefile дорог (в Git не хранятся)
gis/settlements/       опциональный Shapefile населённых пунктов
```

Старые веса дорог и неиспользуемые материалы на рабочем компьютере находятся
в `archive/unused/`. Эта папка добавлена в `.gitignore` и в GitHub не попадает.

## Запуск

Требования: Python 3.10+, Node.js 18+.

```bash
# бэкенд
pip install -r backend/requirements.txt
python -m uvicorn app.main:app --reload --port 8000 --app-dir backend

# фронтенд
cd frontend && npm install && npm run dev
```

Или всё сразу из корня: `npm start`.

Фронтенд: http://localhost:5173, API: http://localhost:8000 (документация — `/docs`).

## Тесты

```bash
cd backend && python -m pytest
cd frontend && npm run build
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ROADS_SHP_PATH` | путь к Shapefile дорог | `gis/roads/roads.shp` |
| `SETTLEMENTS_SHP_PATH` | путь к Shapefile населённых пунктов (опционально) | `gis/settlements/settlements.shp` |
| `R0_METERS` | характерное расстояние для `road_influence` в ответе ИИ-метода | `500` |
| `METRIC_CRS` | метрическая CRS (иначе UTM по центроиду) | пусто |
| `OSM_ENABLED` | использовать Overpass для GeoJSON и резерва расстояний | `1` |
| `OSM_TIMEOUT_SECONDS` | таймаут запроса к Overpass | `1.5` |
| `OSM_FAILURE_COOLDOWN_SECONDS` | пауза после ошибки Overpass | `300` |
| `OSM_CACHE_TTL_SECONDS` | TTL кэша ответов Overpass | `600` |
| `FIRE_RISK_MODEL_ENABLED` | включить модель по снимку | `1` |
| `FIRE_RISK_MODEL_ID` | идентификатор модели на Hugging Face | `prithivMLmods/Fire-Risk-Detection` |
| `FIRE_RISK_MODEL_CACHE_DIR` | каталог кэша весов | кэш Hugging Face |
| `FIRE_RISK_MAX_IMAGE_BYTES` | максимальный размер снимка | `20971520` |
| `FIRE_ML_MODEL_PATH` | путь к модели по реестру пожаров | `ml/fire_point_model/fire_point_model.joblib` |
| `FIRE_ML_DATA_DIR` | папка со слоями данных заказчика | `информация от заказчика/БНЦ` |
| `ROAD_SEGMENTATION_MODEL_ID` | Hugging Face ID модели дорог | `kishan4444/upernet-swin-openearthmap-road-segmentation` |
| `ROAD_MODEL_CACHE_DIR` | каталог кэша модели дорог | кэш Hugging Face |
| `ROAD_MODEL_DEVICE` | устройство инференса (`cpu`, `cuda`) | автоопределение |
| `ROAD_SEGMENTATION_THRESHOLD` | порог вероятности класса дороги | `0.35` |

## Технологии

FastAPI, SQLAlchemy (SQLite), PyJWT, GeoPandas/Shapely/PyProj, React, Leaflet,
react-leaflet, PyTorch + Transformers/UPerNet (сегментация дорог),
Transformers + SigLIP2 (предсказание класса поверхности по снимку).
